Forecasting planting dates from field history

Python · pandas · XGBoost · GeoPandas  |  Download the notebook (.ipynb)

When will each field be planted this spring? Planting date drives yield potential, input timing, and logistics like seed delivery and in-season product demand. A field's own history says a lot: some growers are always early, some fields are always wet. This notebook turns each field's past seasons into horizontal time-series features (one column per variable per lag year) and trains an XGBoost regressor on them.

About the data. The original model ran in PySpark on a few hundred thousand real field-seasons joined to soil survey (SSURGO) attributes and monthly weather. Fields, soils, and weather here are simulated with generic column names. The feature construction, model, and evaluation follow the original, with the fixes noted below.

import numpy as np
import pandas as pd
import geopandas as gpd
import matplotlib.pyplot as plt
from xgboost import XGBRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error

pd.set_option("display.width", 130)

COUNTIES_URL = "https://www2.census.gov/geo/tiger/GENZ2023/shp/cb_2023_us_county_20m.zip"
REGION = ["ND", "SD", "NE", "MN", "IA", "WI", "IL", "IN", "OH"]
states = gpd.read_file(STATES_URL).query("STUSPS in @REGION").to_crs(4326)
counties = gpd.read_file(COUNTIES_URL).query("STUSPS in @REGION").to_crs(4326)
CROP_COLORS = {"Corn": "#d4a017", "Soybeans": "#4c8c2b"}

1. Simulated field-seasons

There are 6,000 fields across nine states, observed 2011-2024. Planting date (day of year) depends on latitude, crop (soybeans go in later), soil (finer, poorly drained soils dry out later), the grower's own habit, and the year. 2012 is an early, warm spring and 2013 and 2019 are very wet, late springs, as they really were. Each spring's January-March weather is partly predictive of how late that year runs. About 10% of field-seasons are missing.

rng = np.random.default_rng(3)
YEARS = list(range(2011, 2025))
YEAR_EFFECT = {2011: 4, 2012: -9, 2013: 12, 2014: 3, 2015: 1, 2016: -2, 2017: 3, 2018: 5, 2019: 18, 2020: -2, 2021: -7, 2022: 7, 2023: -3, 2024: 2}

shape = states.union_all()
minx, miny, maxx, maxy = shape.bounds
pts = []
while len(pts) < 6000:
    cand = gpd.points_from_xy(rng.uniform(minx, maxx, 6000), rng.uniform(miny, maxy, 6000))
    pts.extend([p for p in cand if shape.contains(p)])
fields = gpd.GeoDataFrame({"field_id": [f"F{i:05d}" for i in range(6000)]}, geometry=pts[:6000], crs=4326)
fields = fields.sjoin(counties[["GEOID", "STUSPS", "geometry"]], predicate="within") \
    .rename(columns={"GEOID": "county_fips", "STUSPS": "state"}).drop(columns="index_right")
fields["lat"], fields["lon"] = fields.geometry.y, fields.geometry.x
n = len(fields)
fields["slope_pct"] = rng.gamma(1.5, 1.4, n).round(1)
fields["elev_m"] = (180 + 25 * (fields.lat - 37) + 6 * (-fields.lon - 82) + rng.normal(0, 30, n)).round(0)
fields["frost_free_days"] = (195 - 3.3 * (fields.lat - 37) + rng.normal(0, 4, n)).round(0)
fields["sand_pct"] = rng.uniform(5, 70, n).round(1)
fields["cec"] = (32 - 0.35 * fields.sand_pct + rng.normal(0, 3, n)).clip(3).round(1)
fields["habit"] = rng.normal(0, 4, n)
fields["rotation"] = rng.choice(["corn-soy", "continuous corn", "continuous soy"], p=[0.78, 0.15, 0.07], size=n)
fields["phase"] = rng.integers(0, 2, n)

weather = {}
for s in REGION:
    for y in YEARS:
        anomaly = YEAR_EFFECT[y] + rng.normal(0, 3)
        weather[(s, y)] = {"spring_temp_c": round(-6 + rng.normal(0, 1.2) - 0.08 * anomaly, 1),
                           "spring_precip_mm": round(max(40, 160 + 9 * anomaly + rng.normal(0, 20)), 0),
                           "spring_et_mm": round(55 + rng.normal(0, 6) - 0.4 * anomaly, 1), "anomaly": anomaly}

rows = []
for f in fields.itertuples():
    for i, y in enumerate(YEARS):
        if rng.random() < 0.10:
            continue
        crop = {"corn-soy": ["Corn", "Soybeans"][(i + f.phase) % 2], "continuous corn": "Corn",
                "continuous soy": "Soybeans"}[f.rotation]
        w = weather[(f.state, y)]
        doy = (104 + 2.3 * (f.lat - 38) + (9 if crop == "Soybeans" else 0) + f.habit + w["anomaly"]
               + 0.09 * (35 - f.sand_pct) + rng.normal(0, 4.5))
        corn = crop == "Corn"
        rows.append({"field_id": f.field_id, "season_year": y, "crop": crop,
                     "planting_doy": round(doy), "season_precip_mm": round(w["spring_precip_mm"] * 3.1 + rng.normal(0, 40)),
                     "season_temp_c": round(21.5 - 0.3 * (f.lat - 38) + rng.normal(0, 0.6), 1),
                     "n_lb_ac": round(rng.normal(165, 25) if corn else max(0, rng.normal(6, 8))),
                     "yield_bu_ac": round((195 if corn else 58) * rng.normal(1, 0.1) * (1 - 0.004 * max(0, doy - 125)), 1),
                     **{k: v for k, v in w.items() if k != "anomaly"}})
seasons = pd.DataFrame(rows)
for col in ["yield_bu_ac", "n_lb_ac", "season_precip_mm"]:               # scattered missing values
    seasons.loc[seasons.sample(frac=0.04, random_state=len(col)).index, col] = np.nan
fields = pd.DataFrame(fields.drop(columns=["geometry", "habit", "rotation", "phase"]))

print(f"{len(seasons):,} field-seasons on {seasons.field_id.nunique():,} fields, {seasons.season_year.min()}-{seasons.season_year.max()}")

2. Horizontal time-series features

Each training row is one field × target year. Its features come in two kinds:

  • Known at forecast time: state, this year's planned crop, soils, and January-March weather of the target year.
  • History: crop, planting date, yield, N rate, and season weather from each of the previous five seasons, pivoted wide.

The key change from my first version: lag columns are named relative to the target year (lag1_ = last season, lag2_ = two seasons back) instead of by calendar year (planting_day_of_year_2018). With calendar-year names, a model trained to predict 2024 can't be applied to 2025. With relative names, rows from several target years can be stacked into one training set, and the same model rolls forward.

Three summary features are added on top of the raw lags: the field's mean and spread of past planting dates, and its mean for the same crop it's planting this year. A model can find these on its own, but it learns faster and steadier when they're handed to it.

HIST = ["crop", "planting_doy", "yield_bu_ac", "n_lb_ac", "season_precip_mm", "season_temp_c"]
KNOWN = ["spring_temp_c", "spring_precip_mm", "spring_et_mm"]
SOIL = ["slope_pct", "elev_m", "frost_free_days", "sand_pct", "cec"]
N_LAGS = 5


def build_rows(target_year):
    target = seasons[seasons.season_year == target_year][["field_id", "season_year", "crop", "planting_doy"] + KNOWN]
    hist = seasons[seasons.season_year.between(target_year - N_LAGS, target_year - 1)].copy()
    hist["lag"] = target_year - hist.season_year
    wide = hist.pivot(index="field_id", columns="lag", values=HIST)
    wide.columns = [f"lag{lag}_{var}" for var, lag in wide.columns]
    summ = hist.groupby("field_id").planting_doy.agg(n_hist="size", hist_mean_doy="mean", hist_std_doy="std")
    same = hist.merge(target[["field_id", "crop"]], on=["field_id", "crop"]).groupby("field_id").planting_doy.mean()
    return (target.merge(wide, left_on="field_id", right_index=True)
                  .merge(summ, left_on="field_id", right_index=True)
                  .merge(same.rename("hist_mean_doy_same_crop"), left_on="field_id", right_index=True, how="left")
                  .merge(fields[["field_id", "state", "county_fips"] + SOIL], on="field_id"))


data = pd.concat([build_rows(y) for y in range(2016, 2025)], ignore_index=True)
data = data[data.n_hist >= 4]                          # need at least 4 of the last 5 seasons
print(f"{len(data):,} field x target-year rows; columns like: {', '.join(c for c in data.columns if c.startswith('lag1_'))}")
print(f"Missing lag values kept as NaN: {data.filter(like='lag').isna().mean().mean():.1%} of lag cells")

Two more fixes from the original:

  • Don't drop rows with any missing value. dropna() threw away about 25% of fields, mostly ones missing a single season. XGBoost routes missing values down a learned default branch, so NaN can stay.
  • Don't declare 0 as "missing". The original passed missing=0.0, which also hid real zeros, such as 0 lb N on soybeans.

3. Train on past years, test on the next one

The original used a random 80/20 split of fields for a single target year. Here the model trains on target years 2016-2022 (which include the extreme 2019 spring), uses 2023 for early stopping, and is tested on 2024, exactly the way it would be used: forecasting a season it has never seen. Seven training years also give it a chance to learn how January-March weather shifts a whole season earlier or later.

cat_cols = ["state", "crop"] + [f"lag{l}_crop" for l in range(1, N_LAGS + 1)]
features = (["state", "crop"] + KNOWN + SOIL + ["hist_mean_doy", "hist_std_doy", "hist_mean_doy_same_crop"]
            + [c for c in data.columns if c.startswith("lag")])
X = data[features].copy()
for c in cat_cols:
    X[c] = X[c].astype("category")
num = [c for c in features if c not in cat_cols]
X[num] = X[num].astype(float)
y = data.planting_doy

train, valid, test = data.season_year.between(2016, 2022), data.season_year == 2023, data.season_year == 2024
model = XGBRegressor(n_estimators=1500, learning_rate=0.03, max_depth=5, subsample=0.8, colsample_bytree=0.7,
                     tree_method="hist", enable_categorical=True, early_stopping_rounds=50, random_state=42)
model.fit(X[train], y[train], eval_set=[(X[valid], y[valid])], verbose=False)
pred = pd.Series(model.predict(X[test]), index=X[test].index)
print(f"train {train.sum():,} | valid {valid.sum():,} | test {test.sum():,} rows; best iteration {model.best_iteration}")

train 34,895 | valid 4,996 | test 4,997 rows; best iteration 167

4. Against simple baselines

A forecast is only useful if it beats what a planner could guess without a model:

  • Field's own average: the mean of the field's past planting dates for the same crop (any crop if none).
  • State × crop last year: last season's average for the field's state and crop.
t = data[test].copy()
hist = seasons[seasons.season_year < 2024]
own = hist.groupby(["field_id", "crop"]).planting_doy.mean()
own_any = hist.groupby("field_id").planting_doy.mean()
t["base_field"] = [own.get((f, c), own_any.get(f)) for f, c in zip(t.field_id, t.crop)]
last = hist[hist.season_year == 2023].merge(fields[["field_id", "state"]], on="field_id") \
           .groupby(["state", "crop"]).planting_doy.mean()
t["base_state"] = [last[(s, c)] for s, c in zip(t.state, t.crop)]
t["model"] = pred

A field's own average is a tough benchmark: most of the variation between fields is the grower's habit and location, which that average already captures. The model's edge comes from reading this year's spring weather, which shifts every field together. In my first attempt, trained on only three target years, the model actually lost to the field average. It needed more seasons to learn what a wet spring does.

5. What drives the forecast

imp = pd.Series(model.get_booster().get_score(importance_type="gain"))
imp = (imp / imp.sum()).sort_values().tail(14)
ax = imp.plot(kind="barh", figsize=(6.5, 4), color="#4c8c2b")

This spring's precipitation carries the most weight. It's the only clue to whether the whole season will run early or late. Next come the field's history and rotation: the crop two seasons back (in a corn-soybean rotation, that's this year's crop again), its average planting date for this crop, and the current crop. That matches agronomic intuition. Who farms the field and what goes in set the baseline, and the spring weather shifts the whole year earlier or later.

Takeaways

  • Name lags relative to the target. lag1_, lag2_, ... make the feature table reusable across target years, so you can train on several seasons and forecast the next one.
  • Let the model handle missing history. Dropping incomplete rows loses a quarter of the fields for little gain. Gradient boosting handles NaN natively.
  • Validate forward in time and compare against the obvious baselines. A field's own average is a strong benchmark. Beating it takes enough training seasons to learn the year-to-year signal.
  • Map the residuals. A regional bias is easy to miss in a single error metric.
